How to create a monthly KPI report PDF from a CSV with AI

From a spreadsheet of monthly numbers to a short, answer-first PDF report with KPI tiles, trend charts and commentary, built by a script so the prose cannot disagree with the data.

By Boardroom Skills · Updated 2026-11-09 · About 4 min read

Short version: keep the numbers in a CSV, keep the words in a notes file that refers to those numbers by name, and let a script build the PDF. Then the commentary cannot contradict the data, and next month you change one file and rebuild. The free monthly-kpi-report skill does exactly this.

Why a script beats pasting a CSV into a chat

You can paste a table into an AI chat and ask for a report. It usually works once. The trouble starts in month two: the layout changes, a number in the paragraph is rounded differently from the chart, and you cannot tell which figure the model quietly retyped. Using Claude Code to run a script avoids that. The data flows from the file to the chart and the text by code, not by retyping.

Step 1: Shape the CSV

Use one row per month and one column per metric. The first column is the month as YYYY-MM. Percentages are plain numbers (62.4 means 62.4%). Include at least the reporting month and the month before, and ideally twelve months so trend charts have something to show.

month,revenue,gross_margin,new_customers,churn,cac,cash
2025-04,276391,60.6,123,2.26,413,857503
2025-05,283195,60.8,126,2.34,409,862295

This is a “wide” layout. If your export is long (one row per metric per month), ask Claude Code to pivot it first and show you the result before you go on.

Step 2: Decide the answer before you write anything

A good management report leads with its conclusion. This is the Pyramid Principle: state the answer, give up to three supporting reasons, then show evidence. Before writing, look at each metric against last month and against target and finish this sentence: “The one thing the reader needs to know or decide is…”

Write headlines that carry a verdict. “Revenue is 2% behind plan because churn spiked” works. “Revenue update” does not. If you are unsure of the cause, say so in the text (“cause to be confirmed”) rather than inventing a plausible one. Causes are the one thing the data cannot tell the agent.

Step 3: Write the notes file

The skill reads a short markdown-style file. It has a few header lines, a metrics list, and the text of the report:

company: Tidewater Goods Co.
period: 2026-09
currency: $

## Metrics
revenue | Revenue | currency | up | 470000 | bar
churn   | Monthly churn | percent | down | 2.0

## Headline
Revenue grew {revenue.mom} to {revenue} in {period_label}, but
churn at {churn} is the one issue that needs a decision.

Each metric line is: key, label, type, whether higher is better, target (optional) and chart style (optional). Marking churn and cost metrics as “down” matters: it tells the report that a fall is good news, so the colour and arrow are right.

Step 4: Use tokens for every number

Notice the curly-brace tokens above. {revenue} is the latest value, {revenue.prev} last month, {revenue.mom} the month-on-month change, {revenue.target} the target and {revenue.vs_target} the gap to it. The script fills them from the CSV, and it aborts if you reference a key that does not exist. That one rule removes the most common failure in AI-written reports: a sentence that says 4.1% when the chart says 3.9%.

The rest of the notes file has two to four key points (three is ideal), each tied to a metric and a short paragraph, then risks and next steps as bullets of the form text | owner | due date or mitigation. Give owners and dates only if you know them.

Step 5: Install the skill and build

git clone https://github.com/boardroomskills/boardroom-skills.git
cp -r boardroom-skills/skills/monthly-kpi-report ~/.claude/skills/
pip install -r ~/.claude/skills/monthly-kpi-report/requirements.txt

Then ask Claude Code: “Use the monthly-kpi-report skill to build a report from data.csv. Ask me for targets and the likely causes of any misses; do not guess them.” The script call underneath is:

python3 scripts/build_report.py --csv data.csv --notes notes.md --out report.pdf

It uses reportlab and matplotlib, needs no network access and no API key, and uses the built-in Helvetica font so there is nothing to install for typography.

Step 6: Check every page

Do not forward the PDF unread. Render it and look:

pdftoppm -png -r 60 report.pdf out/p

Then run through this list:

  • Is any text clipped, or does it collide with a chart label?
  • For lower-is-better metrics (churn, CAC), do the arrow and colour show an increase as bad?
  • Does every number in the prose match the appendix table?
  • Is any section empty, or does placeholder text remain?
  • Does the headline sentence still say something true after you re-read the data?

Making it a monthly routine

The real payoff is month two. Keep the notes file in the same folder as the CSV and treat it like a template. Each month, append the new row to the CSV, change period:, update targets if they moved, and rewrite only the parts that are your judgement: the headline verdict, the causes, the risks. Because the figures are tokens, you do not retype any of them. Keep each month’s PDF and its two input files together so you can reproduce a past report exactly. If you have a repository for your reporting, commit the inputs, not just the output, and a colleague can rebuild the same report without you.

Limits to know about

  • One target per metric, for the reporting month only.
  • Four to six headline metrics. More than that and the first page stops being readable.
  • Wide CSV only, and the layout is fixed (A4 portrait). A different page size or a branded template means editing the script.
  • The script computes; it does not explain. Causes, decisions and owners come from you.
